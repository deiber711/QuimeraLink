# Política de seguridad de QuimeraLink

## Versiones con soporte

QuimeraLink es un proyecto estudiantil en desarrollo. Las correcciones de seguridad se aplican primero en la rama `main`.

| Versión | Soporte de seguridad |
| --- | --- |
| Rama `main` | En mantenimiento |
| Versiones anteriores y ejecutables archivados | Sin actualizaciones de seguridad garantizadas |

## Cómo reportar una vulnerabilidad

Envía el reporte de forma privada a **lomwit@proton.me** con el asunto **[QuimeraLink] Reporte de seguridad**. Evita publicar los detalles en issues, pull requests o comentarios.

Incluye, si es posible:

- La versión o el commit de QuimeraLink y tu sistema operativo.
- Una descripción breve del problema y de su posible impacto.
- Los pasos mínimos para observar el problema en un entorno de prueba autorizado.
- Capturas o registros relevantes con los datos sensibles ocultos.

Usa datos ficticios y elimina contraseñas, tokens, cookies, información personal y parámetros privados de las URLs antes de enviar el reporte.

## Qué se considera un problema de seguridad

Esta política cubre problemas de QuimeraLink, como la exposición de datos, la omisión de restricciones al inspeccionar enlaces o el acceso a archivos locales sin autorización.

Si el programa clasificó mal un enlace, indícalo como falso positivo o falso negativo. Si además detectaste un problema de privacidad o de seguridad en la aplicación, repórtalo por el canal privado.

## Qué esperar después del reporte

Intentaré confirmar la recepción en un plazo de siete días. Si necesito más información, te la pediré por el mismo canal. Si se confirma el problema, te informaré sobre el estado y la corrección cuando haya novedades. Si el reporte queda fuera del alcance, te explicaré el motivo cuando sea posible.

El tiempo de resolución depende de la gravedad, la complejidad y mi disponibilidad. Te pido mantener los detalles en privado mientras coordinamos la corrección y su divulgación.

# English Version

# QuimeraLink Security Policy

## Supported Versions

QuimeraLink is a student project under active development. Security fixes are applied to the `main` branch first.

| Version | Security support |
| --- | --- |
| `main` branch | Actively maintained |
| Older releases and archived executables | Security updates are not guaranteed |

## Reporting a Vulnerability

Send your report privately to **lomwit@proton.me** with the subject **[QuimeraLink] Security Report**. Please avoid sharing vulnerability details in issues, pull requests, or comments.

If possible, include:

- The QuimeraLink version or commit and your operating system.
- A brief description of the issue and its potential impact.
- The minimum steps needed to observe the issue in an authorized test environment.
- Relevant screenshots or logs with sensitive information redacted.

Use sample data and remove passwords, tokens, cookies, personal information, and private URL parameters before sending the report.

## Scope

This policy covers vulnerabilities in QuimeraLink, such as data exposure, bypasses of restrictions on link inspection, or unauthorized access to local files.

If QuimeraLink misclassifies a link, describe it as a false positive or false negative. If you also find a privacy or security issue in the application, report it privately through the channel above.

## What to Expect

I aim to acknowledge your report within seven days. If I need more information, I will follow up through the same channel. If I confirm the issue, I will share updates as they become available. If the report is outside the scope of this policy, I will explain why when possible.

Resolution time depends on severity, complexity, and my availability. Please keep vulnerability details private while we coordinate a fix and its disclosure.
